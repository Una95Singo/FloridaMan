# Email send — setup note (documented stub)

The three templates in this directory (`trigger-email.txt`,
`expert-email.txt`, `scorecard-email.txt`) are the specified interface.
No ESP is mandated — the provider is an operator choice (PRD §4, OQ-1).

## What's implemented

- **Templates:** complete, with `{{placeholders}}` the pipeline fills at
  send time (storm, run number, trace URL, signed action URLs, unsubscribe
  URL). The run-004 trigger and expert emails above are filled with real
  data as the reference rendering.
- **Subscribe form** (`../subscribe.html`): the approved UI. Static hosting
  cannot process it — see "Wiring" below.

## What needs a live mail service (the stub)

1. **Pick an ESP** (Resend, Postmark, Buttondown, or equivalent —
   transactional email with list-unsubscribe support).
2. **Subscribe endpoint:** point the form on `subscribe.html` at the ESP's
   subscribe endpoint (or a thin serverless function that calls it).
   Required fields: `email`, `scope` (all | storm | bonds), `frequency`
   (trigger | digest). Store nothing beyond what's needed to send.
3. **Send-on-publish:** the pipeline's `Notify` step (PRD §5.1) renders
   `trigger-email.txt` per published run and sends to all subscribers
   whose scope matches; renders `expert-email.txt` to the expert only.
   Never sends on heartbeat silence (TRG-005).
4. **Signed action links:** the expert email's Approve/Correct/Challenge
   URLs carry single-use signed tokens (72h expiry), generated by the
   expert gate (`pipeline/floridaman/gate.py`). Approve is one tap;
   Correct/Challenge open the two-field form (what changed + why).
5. **Secrets:** API keys live in the operator's environment / ESP
   dashboard — never in this repo, never in these files.

## Acceptance

- A published run triggers exactly one email per matching subscriber,
  median trigger-to-send ≤ 2h (PRD success metric 2).
- Every email carries a working one-click unsubscribe.
- The word "marks" in the pricing sense appears in zero sent emails.
